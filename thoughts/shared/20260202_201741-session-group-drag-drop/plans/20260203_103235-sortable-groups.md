# Sortable Groups Implementation Plan

## Overview

Implement sortable for groups to enable reordering while preserving the ability to nest groups inside each other. Currently groups use `useDraggable` + `useDroppable` which can't distinguish between "reorder with sibling" vs "nest into sibling". This plan adds proper sortable behavior where:
1. Dragging between groups reorders them within the same parent
2. Dropping directly ON a group header (with visual indicator) nests the dragged group inside it

## Current State Analysis

### GroupRow (SessionList.tsx:294-533)
- Uses `useDraggable` for drag initiation
- Uses `useDroppable` for receiving drops
- Both refs combined on the group header div
- No way to distinguish drop position (on header vs between items)

### buildGroupTree (SessionList.tsx:49-121)
- Sorts groups alphabetically by name: `node.children.sort((a, b) => a.name.localeCompare(b.name))`
- Ignores the `order` field from the backend
- This needs to change to respect saved order

### Backend Support
- `reorderGroups` API already exists in `groupsApi.ts:75-82`
- Backend endpoint exists in `group_handlers.go`
- Groups have `order` field in the type definition

### Key Discovery
The current code in `handleDragEnd` (line 819-824) always nests when dropping on a group:
```typescript
// Dropping a group ON another group always means "move into" (nest)
await moveGroup({
  path: draggedGroupPath,
  newParentPath: targetGroupPath,
});
```

## Desired End State

### Reordering Behavior:
- Dragging a group near the TOP or BOTTOM edge of a sibling group reorders them
- Visual indicator shows where the group will be inserted (line/gap between groups)
- Groups within the same parent can be reordered by dragging

### Nesting Behavior:
- Dragging a group to the CENTER of another group's header nests it inside
- Visual indicator changes (highlight fills the header) when in "nest mode"
- Hovering in center zone for 300ms+ triggers auto-expand if collapsed

### Visual Feedback:
- **Reorder mode**: Horizontal line appears between groups where drop will occur
- **Nest mode**: Group header gets accent background highlight (existing behavior)

## What We're NOT Doing

- Keyboard-based drag-and-drop
- Multi-select drag
- Animation refinements beyond basic feedback
- Drag preview customization for groups

## Implementation Approach

Use a "drop zone" approach where we detect the vertical position within the group header:
- **Top 25%**: Insert BEFORE this group (reorder)
- **Middle 50%**: Nest INTO this group
- **Bottom 25%**: Insert AFTER this group (reorder)

This is achieved by:
1. Using `useSortable` for sortable IDs but with custom collision detection
2. Tracking mouse position in `onDragOver` to determine drop intent
3. Showing different visual indicators based on drop zone

#### 2. Update handleDragOver for Groups

Detect drop zone based on mouse position within group header.

Add to `handleDragOver`:
```typescript
const handleDragOver = useCallback((event: DragOverEvent) => {
  const { active, over } = event;

  // ... existing session handling ...

  const activeData = active.data.current as DragItem | undefined;
  if (!activeData) return;

  // Handle group drag over another group
  if (activeData.type === "group" && over) {
    const overId = String(over.id);

    // Check if hovering over a group drop target
    if (overId.startsWith("group-drop-")) {
      const targetPath = overId.replace("group-drop-", "");
      const draggedPath = activeData.id as string;

      // Can't drop on self or descendants
      if (targetPath === draggedPath || targetPath.startsWith(draggedPath + "/")) {
        setGroupDropZone(null);
        return;
      }

      // Determine zone based on pointer position
      const rect = over.rect;
      const pointerY = event.activatorEvent instanceof PointerEvent
        ? event.activatorEvent.clientY
        : null;

      if (rect && pointerY !== null) {
        const relativeY = pointerY - rect.top;
        const height = rect.height;
        const percentage = relativeY / height;

        // Check if same parent (siblings can reorder)
        const draggedParent = draggedPath.includes("/")
          ? draggedPath.substring(0, draggedPath.lastIndexOf("/"))
          : "";
        const targetParent = targetPath.includes("/")
          ? targetPath.substring(0, targetPath.lastIndexOf("/"))
          : "";
        const areSiblings = draggedParent === targetParent;

        let zone: "before" | "inside" | "after";
        if (areSiblings) {
          // Siblings: top 30% = before, middle 40% = inside, bottom 30% = after
          if (percentage < 0.3) {
            zone = "before";
          } else if (percentage > 0.7) {
            zone = "after";
          } else {
            zone = "inside";
          }
        } else {
          // Non-siblings: always nest (no reorder option)
          zone = "inside";
        }

        setGroupDropZone({ groupPath: targetPath, zone });
      }
    } else {
      setGroupDropZone(null);
    }
  }
}, [sessions, groups]);
```

**Note**: The `event.activatorEvent` approach may not work reliably. Alternative: use `onDragMove` or track pointer position separately.

#### 2. Update handleDragEnd for Groups

**File**: `client/src/components/Sessions/SessionList.tsx`
**Changes**: Handle reorder vs nest based on drop zone

Replace the group handling section:
```typescript
// Handle group drag
if (activeData.type === "group") {
  const draggedGroupPath = activeData.id as string;
  const savedGroupDropZone = groupDropZoneRef.current;

  // Clear ref
  groupDropZoneRef.current = null;
  setGroupDropZone(null);

  if (overData?.type === "group" && savedGroupDropZone) {
    const targetGroupPath = savedGroupDropZone.groupPath;

    // Validate: can't drop onto self or own descendants
    if (targetGroupPath === draggedGroupPath || targetGroupPath.startsWith(draggedGroupPath + "/")) {
      return;
    }

    if (savedGroupDropZone.zone === "inside") {
      // NEST: Move into target group
      await moveGroup({
        path: draggedGroupPath,
        newParentPath: targetGroupPath,
      });
    } else {
      // REORDER: Move before or after target
      const draggedParent = draggedGroupPath.includes("/")
        ? draggedGroupPath.substring(0, draggedGroupPath.lastIndexOf("/"))
        : "";

      // Get siblings at this level
      const siblingGroups = groups
        .filter(g => {
          const parent = g.path.includes("/")
            ? g.path.substring(0, g.path.lastIndexOf("/"))
            : "";
          return parent === draggedParent;
        })
        .sort((a, b) => a.order - b.order);

      const oldIndex = siblingGroups.findIndex(g => g.path === draggedGroupPath);
      let newIndex = siblingGroups.findIndex(g => g.path === targetGroupPath);

      // Adjust for before/after
      if (savedGroupDropZone.zone === "after") {
        newIndex = newIndex + 1;
      }
      // If moving down, account for removal of dragged item
      if (oldIndex < newIndex) {
        newIndex = newIndex - 1;
      }

      if (oldIndex !== -1 && newIndex !== -1 && oldIndex !== newIndex) {
        const newOrder = arrayMove(siblingGroups, oldIndex, newIndex);
        await reorderGroups({
          parentPath: draggedParent,
          groupPaths: newOrder.map(g => g.path),
        });
      }
    }
  } else if (overData?.type === "root") {
    // Dropping on root - move to top level
    const draggedParent = draggedGroupPath.includes("/")
      ? draggedGroupPath.substring(0, draggedGroupPath.lastIndexOf("/"))
      : "";
    if (draggedParent !== "") {
      await moveGroup({
        path: draggedGroupPath,
        newParentPath: "",
      });
    }
  }
}
```

## Phase 5: Bug Fixes

### Overview
During implementation, several bugs were discovered and fixed.

### Bugs Fixed:

#### 1. Pointer events not firing during drag
- **Problem**: `onPointerMove` on group headers wasn't firing because dnd-kit captures pointer during drag
- **Solution**: Use global `window.addEventListener("pointermove")` and compute zone in `handleDragOver` using `over.rect` and a `pointerPositionRef`

#### 2. Stale closure in handleDragOver
- **Problem**: After a reorder, subsequent drags showed redundant "same position" indicators because `handleDragOver` used a stale `groups` reference
- **Root cause**: `groups` was used inside `handleDragOver` but not in its dependency array
- **Solution**: Add `groups` to the `handleDragOver` dependency array: `[sessions, groups]`

#### 3. Optimistic updates for immediate UI feedback
- **Problem**: After reorder API call, the cache invalidation triggered a refetch, but there was a brief moment where calculations used stale data
- **Solution**: Added optimistic updates to `reorderGroups` mutation in `groupsApi.ts` to immediately update order values in cache

## Testing Strategy

### Manual Testing Steps:

1. **Reorder Test - Top Level:**
   - Create groups A, B, C at top level
   - Drag C to top edge of A - order should become C, A, B
   - Drag B to bottom edge of C - order should become C, B, A

2. **Reorder Test - Nested:**
   - Create subgroups X, Y, Z under group A
   - Drag Z to before X - order should become Z, X, Y
   - Verify order persists after refresh

3. **Nest Test - Sibling:**
   - Have groups A and B at same level
   - Drag B to CENTER of A (not edges) - B becomes child of A
   - Verify B appears nested under A

4. **Nest Test - Non-Sibling:**
   - Have group A at root, group B/C nested
   - Drag A onto C - A becomes child of B (inside C's parent)
   - Non-siblings always nest, no reorder option

5. **Edge Cases:**
   - Try to drop group onto itself - should be no-op
   - Try to drop parent onto its child - should be no-op
   - Drag while scrolling
   - Rapid drag operations

### Edge Cases:
- Only 2 groups at a level (reorder should still work)
- Single group (no reorder possible, only nest elsewhere)
- Deeply nested groups (3+ levels)
- Collapsed vs expanded groups as drop targets
