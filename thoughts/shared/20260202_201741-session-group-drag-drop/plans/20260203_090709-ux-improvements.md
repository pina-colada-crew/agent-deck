# Drag-and-Drop UX Improvements Plan

## Overview

Improve the drag-and-drop UX for sessions and groups with four key enhancements:
1. Expand the draggable area for session items
2. Fix status circle alignment with group chevrons
3. Enable position selection when moving sessions between groups
4. Make groups draggable for reordering and re-nesting

## Current State Analysis

### SessionItem Layout (SessionItem.tsx)
```
[GripVertical] [StatusCircle Name] ... [MoreVertical]
     ^              ^                       ^
  drag handle   session info            actions menu
  (only drag    (not draggable)
   point)
```

**Issues:**
- Only the tiny GripVertical icon (14px) initiates drag
- GripVertical appears on hover and pushes status circle right, breaking alignment with group chevrons
- Status circle should align with chevrons at depth+1 indent level

### Cross-Group Movement (useDragHandlers.ts:77-83)
When dropping on a group, it calls `updateSession({ group_path })` without position control - session appears at default position (end).

### GroupRow (SessionList.tsx:285-479)
Groups are drop targets via `useDroppable` but NOT draggable. Cannot reorder groups or drag them into other groups.

## Desired End State

### Session Item Layout:

**Resting state:**
```
[StatusCircle] Name ... [MoreVertical]
      ^
   aligned with
   group chevrons
```

**On hover:**
```
[GripVertical][StatusCircle] Name ... [MoreVertical]
      ^            ^
   appears      stays in exact
   to left      same position
```

- Status circle is in the same vertical column as group chevrons (looking down the list, chevrons and status circles align)
- On hover: drag handle appears to the LEFT of the status circle without shifting it
- Entire area from left edge to MoreVertical menu is draggable
- GripVertical icon appears on hover as visual affordance

### Cross-Group Movement:
- Dropping a session on another session in a different group inserts it at that position
- Dropping a session on a group header appends to end of that group

### Group Dragging:
- Groups can be dragged to reorder within their parent
- Groups can be dragged into other groups (re-nesting)
- Visual feedback shows valid drop targets

## What We're NOT Doing

- Keyboard-based drag-and-drop
- Multi-select drag
- Drag groups to root level (already supported, just visual polish)
- Animation refinements

#### 2. Verify Group Row Alignment

**File**: `client/src/components/Sessions/SessionList.tsx`
**Changes**: Verify the padding calculation aligns status circles with sibling subgroup chevrons

**Visual goal** - sessions align with their sibling subgroups, not the parent:
```
[▼ Parent Group]           <- depth 0, paddingLeft = 4px
   [▼ Subgroup A]          <- depth 1, paddingLeft = 16px, chevron in 14px slot
   [● Session 1]           <- depth 1, paddingLeft = 16px, status in 14px slot (ALIGNED!)
   [▼ Subgroup B]          <- depth 1, paddingLeft = 16px
      [● Session 2]        <- depth 2, paddingLeft = 28px
```

**The key insight**: Sessions and their sibling subgroups are at the SAME depth level. A session inside "Parent Group" is at depth 1 (same as Subgroup A and Subgroup B), not depth 0.

**Alignment math:**
- Subgroup at depth N: `paddingLeft = 4 + N * 12px`, then chevron in 14px slot
- Session at depth N (sibling of that subgroup): `paddingLeft = 4 + N * 12px`, status in 14px slot
- Both have the same padding, so chevron and status circle align perfectly!

**Current code check** - sessions are rendered with `depth + 1`:
```tsx
{/* Sessions container currently uses depth+1 */}
<div style={{ paddingLeft: `${4 + (depth + 1) * 12}px` }}>
```

This is CORRECT if `depth` refers to the parent group's depth. When rendering children of a depth-0 group, we pass `depth + 1 = 1` to match sibling subgroups which are also rendered at depth 1.

**Verify the existing code** uses `depth + 1` for session containers (where `depth` is the parent's depth). If subgroups are rendered by recursively calling GroupRow with `depth + 1`, then sessions should also use `depth + 1` for their container padding.

No change needed IF the current implementation already does this correctly. Verify by inspection.

## Phase 2: Cross-Group Position Selection

### Overview
When dragging a session from one group to another, allow dropping it on a specific session in the target group to insert at that position (not just appending to end).

### Changes Required:

#### 1. Update Drag Handler Logic

**File**: `client/src/hooks/useDragHandlers.ts`
**Changes**: Detect when dropping on a session in a different group and insert at that position

Update the `handleDragEnd` function:

```typescript
const handleDragEnd = useCallback(async (event: DragEndEvent) => {
  const { active, over } = event;

  setActiveItem(null);
  setOverTarget(null);

  if (!over || active.id === over.id) {
    return;
  }

  const draggedItem = active.data.current as DragItem;
  const dropTarget = over.data.current as { type: "session" | "group" | "root"; path?: string } | undefined;

  if (!draggedItem || !dropTarget) return;

  try {
    // Handle session drag
    if (draggedItem.type === "session") {
      // Dropping on another session
      if (dropTarget.type === "session") {
        const targetSession = sessions.find(s => s.id === over.id);
        const targetSessionGroupPath = targetSession?.group_path || "";

        if (targetSessionGroupPath === draggedItem.groupPath) {
          // SAME GROUP: Reorder within group
          const groupSessions = sessions
            .filter(s => (s.group_path || "") === targetSessionGroupPath)
            .sort((a, b) => (a.position || 0) - (b.position || 0));

          const oldIndex = groupSessions.findIndex(s => s.id === draggedItem.id);
          const newIndex = groupSessions.findIndex(s => s.id === over.id);

          if (oldIndex !== -1 && newIndex !== -1 && oldIndex !== newIndex) {
            const newOrder = [...groupSessions];
            const [removed] = newOrder.splice(oldIndex, 1);
            newOrder.splice(newIndex, 0, removed);

            await reorderSessions({
              groupPath: targetSessionGroupPath,
              sessionIds: newOrder.map(s => s.id),
            });
          }
        } else {
          // DIFFERENT GROUP: Move to target group at specific position
          // First, get sessions in target group
          const targetGroupSessions = sessions
            .filter(s => (s.group_path || "") === targetSessionGroupPath)
            .sort((a, b) => (a.position || 0) - (b.position || 0));

          // Find insertion index (where the target session is)
          const insertIndex = targetGroupSessions.findIndex(s => s.id === over.id);

          // Move the session to the new group
          await updateSession({
            id: draggedItem.id,
            group_path: targetSessionGroupPath || undefined,
          });

          // Now reorder to place it at the correct position
          // The moved session will appear at the end, so we need to reorder
          const newOrder = [...targetGroupSessions];
          // Insert the dragged session at the target position
          newOrder.splice(insertIndex, 0, { id: draggedItem.id } as Session);

          await reorderSessions({
            groupPath: targetSessionGroupPath,
            sessionIds: newOrder.map(s => s.id),
          });
        }
        return;
      }

      // Dropping on group header or root - append to end (existing behavior)
      const targetGroupPath = dropTarget.type === "root" ? "" : (dropTarget.path || "");
      if (targetGroupPath !== draggedItem.groupPath) {
        await updateSession({
          id: draggedItem.id,
          group_path: targetGroupPath || undefined,
        });
      }
    }

    // Handle group drag (existing code)
    if (draggedItem.type === "group") {
      // ... existing group drag logic ...
    }
  } catch (error) {
    console.error("Drag operation failed:", error);
  }
}, [sessions, setActiveItem, setOverTarget, updateSession, reorderSessions, moveGroup]);
```

### Implementation Notes (Post-Implementation):

The cross-group position selection required several additional fixes beyond the original plan:

1. **Visual Preview for Cross-Group Drags** - Added `previewSessions` state to show sessions visually moving to their target position during cross-group drags (same UX as within-group reordering). This was moved inline to `SessionList.tsx` instead of using the separate `useDragHandlers.ts` hook.

2. **Fixed dropTargetRef Being Cleared** - The `dropTargetRef` was being cleared when `handleDragOver` received `active.id === over.id`, which happens during preview rerenders right before `handleDragEnd`. Fixed by preserving the last valid drop target instead of clearing it when this condition occurs.

3. **Fixed activeData.groupPath Mutation Bug** - During drag preview, `activeData.groupPath` would get mutated because the preview modified the session's `group_path`. Fixed by looking up the real `group_path` from the original `sessions` array instead of trusting `activeData.groupPath`.

4. **Fixed Sessions Sorting by Position** - Sessions were being sorted alphabetically by title in `buildGroupTree()`, ignoring the `position` field saved by the reorder API. Fixed to sort by `position` field instead.

5. **Fixed insertIndex Calculation for Same-Group Reorder** - The `insertIndex` in `handleDragOver` was calculated on a filtered list (excluding active session), but `oldIndex` in `handleDragEnd` was calculated on the full list, causing a mismatch where `oldIndex === insertIndex` even when they shouldn't be equal. Fixed by using the full group session list in `handleDragOver`.

**File**: `server/internal/server/group_handlers.go`

```go
// ReorderGroupsRequest is the JSON request for reordering groups within a parent
type ReorderGroupsRequest struct {
	ParentPath string   `json:"parent_path"` // Empty string for root level
	GroupPaths []string `json:"group_paths"` // Ordered list of group paths (siblings only)
}

func (s *Server) handleReorderGroups(w http.ResponseWriter, r *http.Request) {
	var req ReorderGroupsRequest
	if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
		http.Error(w, err.Error(), http.StatusBadRequest)
		return
	}

	s.sessionsMu.Lock()
	defer s.sessionsMu.Unlock()

	// Validate all paths are siblings at the specified parent level
	for _, path := range req.GroupPaths {
		group := s.groupTree.Groups[path]
		if group == nil {
			http.Error(w, "Group not found: "+path, http.StatusNotFound)
			return
		}
		// Check parent matches
		actualParent := ""
		if idx := strings.LastIndex(path, "/"); idx != -1 {
			actualParent = path[:idx]
		}
		if actualParent != req.ParentPath {
			http.Error(w, "Group "+path+" is not a child of "+req.ParentPath, http.StatusBadRequest)
			return
		}
	}

	// Update Order values based on position in array
	for i, path := range req.GroupPaths {
		if group := s.groupTree.Groups[path]; group != nil {
			group.Order = i
		}
	}

	// Rebuild the group list to reflect new order
	s.groupTree.RebuildGroupList()

	if err := s.saveState(); err != nil {
		http.Error(w, err.Error(), http.StatusInternalServerError)
		return
	}

	w.WriteHeader(http.StatusNoContent)
}
```

```typescript
// Handle group drag
if (draggedItem.type === "group") {
  const draggedGroupPath = draggedItem.id as string;

  // Dropping on another group
  if (dropTarget.type === "group") {
    const targetGroupPath = dropTarget.path || "";

    // Check if same parent (reordering siblings)
    const draggedParent = draggedGroupPath.includes("/")
      ? draggedGroupPath.substring(0, draggedGroupPath.lastIndexOf("/"))
      : "";
    const targetParent = targetGroupPath.includes("/")
      ? targetGroupPath.substring(0, targetGroupPath.lastIndexOf("/"))
      : "";

    if (draggedParent === targetParent) {
      // SAME PARENT: Reorder siblings
      // Get all sibling groups at this parent level
      const siblingGroups = groups
        .filter(g => {
          const parent = g.path.includes("/")
            ? g.path.substring(0, g.path.lastIndexOf("/"))
            : "";
          return parent === draggedParent;
        })
        .sort((a, b) => a.order - b.order);

      const oldIndex = siblingGroups.findIndex(g => g.path === draggedGroupPath);
      const newIndex = siblingGroups.findIndex(g => g.path === targetGroupPath);

      if (oldIndex !== -1 && newIndex !== -1 && oldIndex !== newIndex) {
        const newOrder = [...siblingGroups];
        const [removed] = newOrder.splice(oldIndex, 1);
        newOrder.splice(newIndex, 0, removed);

        await reorderGroups({
          parentPath: draggedParent,
          groupPaths: newOrder.map(g => g.path),
        });
      }
      return;
    }

    // DIFFERENT PARENT: Move into target group (existing behavior)
    // Validate: can't move into self or descendant
    if (targetGroupPath === draggedGroupPath || targetGroupPath.startsWith(draggedGroupPath + "/")) {
      console.warn("Cannot move group into itself or its descendants");
      return;
    }

    await moveGroup({
      path: draggedGroupPath,
      newParentPath: targetGroupPath,
    });
  }

  // Dropping on root - move to top level
  if (dropTarget.type === "root") {
    const draggedParent = draggedGroupPath.includes("/")
      ? draggedGroupPath.substring(0, draggedGroupPath.lastIndexOf("/"))
      : "";

    if (draggedParent !== "") {
      // Currently nested, move to root
      await moveGroup({
        path: draggedGroupPath,
        newParentPath: "",
      });
    }
  }
}
```

## Testing Strategy

### Manual Testing Steps:

1. **Phase 1 - Drag Area:**
   - Hover over session, see GripVertical appear (no layout shift)
   - Click anywhere left of ellipsis and drag - should initiate drag
   - Click on ellipsis - should open menu, not drag
   - Verify status circles align with group chevrons at all depths

2. **Phase 2 - Cross-Group Positioning:**
   - Create Group A with sessions 1, 2, 3
   - Create Group B with sessions 4, 5, 6
   - Drag session 1 and drop it on session 5 in Group B
   - Session 1 should appear between 4 and 5 (above 5)
   - Refresh and verify order persists

3. **Phase 3 - Group Dragging:**
   - Create groups A, B, C at top level
   - **Reorder test:** Drag group C above group A - order should become C, A, B
   - **Reorder persistence:** Refresh page - order should still be C, A, B
   - **Nesting test:** Drag group B onto group A - B should become child of A
   - **Un-nesting test:** Drag group B out to Misc. area - B should return to top level
   - **Self-drop prevention:** Try dragging A onto its child B - should be prevented
   - **Nested reorder:** Create subgroups X, Y, Z under A; drag Z above X - order should be Z, X, Y

### Edge Cases:
- Dragging session to empty group
- Dragging last session out of a group
- Dragging group with many nested children
- Rapid drag operations
- Reordering groups when only 2 groups exist at a level
- Reordering nested groups (subgroups within a parent)
- Reordering after moving a group to a new parent (order should be at end initially)
